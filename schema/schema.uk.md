# Документація схеми

Цей документ описує канонічну схему, що використовується в усіх нормалізованих знімках Parquet.

## Версія схеми

| Властивість | Значення |
|---|---|
| **Версія схеми** | 1.1 |
| **Діє з** | v1.1.0 |

Версія схеми відповідає версіонуванню релізів проєкту. Зміни назв колонок, типів або семантики вимагають інкременту мажорної версії.

## Примітки

- Усі рядкові поля обрізані від початкових/кінцевих пробілів.
- Значення `person_type` нормалізовані до односимвольних значень верхнього регістру: `P` або `J`.
- `reg_addr_koatuu` навмисно зберігається як `STRING` для збереження початкових нулів у кодах КОАТУУ.
- `d_reg` розбирається з різних вихідних форматів (`ДД.ММ.РРРР`, `РРРР-ММ-ДД`) у стандартний тип `DATE`.
- `null` використовується для всіх відсутніх або невизначених значень. Жодні сигнальні значення (напр., `0`, `-1`, `невизначено`) не зберігаються.
- Порядок колонок є фіксованим і має бути узгодженим у всіх знімках в межах однієї версії схеми.
- `vin` та `raw_vin` мають значення `null` для всіх записів з вихідних файлів до 2021-01-01 (колонку VIN було додано до джерельного набору у цей момент). `is_valid_vin` також `null` для цих записів.
- `brand` та `model` нормалізовані до латинських символів.
- `record_ids` містить масив ID вихідних записів, агрегованих в один рядок через `GROUP BY` + `ARRAY_AGG`. Сирий набір: ~29 млн записів; після агрегації: ~24 млн записів.
- `n_reg_latin` — транслітерація `n_reg_new` латинськими символами.
- `is_valid_plate` вказує, чи пройшов `n_reg_new` валідацію формату українського номерного знаку.
