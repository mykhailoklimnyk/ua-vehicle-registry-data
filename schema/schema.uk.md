# Документація схеми

Цей документ описує канонічну схему всіх знімків (Parquet і CSV).

## Версія схеми

| Властивість | Значення |
|---|---|
| **Версія схеми** | 3.0 |
| **Діє з** | Перевидання 2026-10 — стосується всіх знімків 2013–2026 |

Зміна назв, типів чи змісту колонок вимагає нової мажорної версії.

### Що змінилось у 3.0

Усі знімки перезібрано з файлів МВС, перелічених у [docs/SOURCES.uk.md](../docs/SOURCES.uk.md),
по одній ревізії джерела на період, одним конвеєром. Попередні релізи змішували три покоління
збирання; 3.0 їх замінює.

1. **`record_id` скрізь.** Масиву `record_ids` (2013 – 2026-03) більше немає. Рядок — один
   унікальний рядок джерела; `record_id` — MD5 його полів, унікальний.
2. **Номерні знаки — до 2026-04-29.** `n_reg_new`, `n_reg_latin`, `is_valid_plate`
   публікуються як у джерелі. З 2026-04-30 номерів немає в джерелі.
3. **`power_kwt` — дробове число** з точністю джерела (`154.6`), не ціле. Значення з десятковою
   комою раніше втрачались.
4. **`d_reg` — Parquet `DATE`**, а не рядок. Булеві в CSV — `true`/`false`.
5. **Порожні колонки не публікуються.** Колонки, яка за період не має опублікованих значень, у файлі немає:
   VIN і `power_kwt` за 2013–2020, номерів з 2026-04-30, `reg_addr_koatuu` з 2026-04-30.

Порядок колонок фіксований; файл містить перелічені колонки мінус ті, що вилучені за правилом 5.

## Примітки

- **Дублікати.** Рядки, однакові в усіх колонках джерела, публікуються один раз. Два рядки, що
  різняться хоч одним полем джерела, — це два рядки, навіть якщо схожі на одну подію.
- **`vin`**: верхній регістр; пробіли, `/`, `-`, лапки прибрано; кириличні двійники латиниці
  замінено (`А В Е К М Н О Р С Т Х І` → `A B E K M H O P C T X I`, `З` → `3`). Решта кириличних
  літер **лишається**, тож такий VIN видимо невалідний. `vin` відповідає `^[A-HJ-NPR-Z0-9]{17}$`
  рівно там, де `is_valid_vin` = true.
- **`is_valid_vin`** перевіряє лише формат (17 символів, без `I O Q`, не починається з `0`).
  Контрольну цифру не перевіряємо: більшість VIN поза Північною Америкою її не використовують.
- **`is_valid_plate`** = true для `AA0000AA` (з 2004), `00000AA` (1995–2004) і кодів онлайн-
  реєстрації. Старіші й спеціальні формати (`16ВР3029`, `АЕАА4125`, дипломатичні `CD001158`) —
  false, однаково в усіх роках.
- **`power_kwt`**: джерело публікує її з 2026-04-30. Значення переноситься на інші реєстрації того
  самого VIN у джерелі, тож може бути і в рядках 2021 – 2026-04-29; VIN за 2013–2020 не публікуються.
- **`capacity`, `own_weight`, `total_weight`** не виправляються. Електромобілі мають об'єм як у
  джерелі (часто порожній).
- **`make_year`** — як у джерелі, крім року, пізнішого за рік реєстрації + 1: такий рік
  неможливий і публікується як NULL. Чотири очевидні описки 2013 року виправлено
  (2088 → 2008, 2033 → 2003 двічі, 2036 → 2006). `make_year = 1900` — заглушка джерела.
- **Заглушки** як значення: `color`/`kind` `Невизначений`, `body` `Невизначений` — це значення
  самого джерела, а не пропуск.
- **`color`**: написання джерела з 2025 `ПОМАРАНЧЕВИЙ (ОРАНЖЕВИЙ)` публікується як `Оранжевий`,
  як у 2013–2024.
- **`oper_name`**: частина кодів має в джерелі кілька формулювань (напр. 308, 100, 540).

## Відповідність колонкам джерела

| Канонічна назва | Колонка джерела |
|---|---|
| `person_type` | `PERSON` |
| `reg_addr_koatuu` | `REG_ADDR_KOATUU` (до 2026-04-29) |
| `oper_code`, `oper_name` | `OPER_CODE`, `OPER_NAME`; з 2026-04-30 одна колонка `CD.OPER_CODE\|\|'-'\|\|CD.OPERAS` |
| `d_reg` | `D_REG` (`YYYY-MM-DD`, `DD.MM.YYYY` або `DD.MM.YY`) |
| `dep_code` | `DEP_CODE` (до 2026-04-29) |
| `dep_name` | `DEP` |
| `brand`, `model` | `BRAND`, `MODEL` (2013–2018: `BRAND` містить і марку, і модель) |
| `vin`, `raw_vin` | `VIN` (з 2021) |
| `make_year` | `MAKE_YEAR` |
| `color`, `kind`, `body`, `purpose`, `fuel` | `COLOR`, `KIND`, `BODY`, `PURPOSE`, `FUEL` |
| `capacity` | `CAPACITY` |
| `power_kwt` | `POWER_KWT` (з 2026-04-30) |
| `own_weight`, `total_weight` | `OWN_WEIGHT`, `TOTAL_WEIGHT` |
| `n_reg_new` | `N_REG_NEW` (до 2026-04-29) |

Назви колонок зіставляються без урахування регістру. `record_id`, `payload`, `secondary_fuel`,
`n_reg_latin`, `is_valid_plate` і `is_valid_vin` — обчислювані.
